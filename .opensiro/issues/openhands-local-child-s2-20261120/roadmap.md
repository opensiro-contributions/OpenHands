## Function ownership

**S2 disturbance:** local siblings editing the same workspace can overwrite each other following an intentional `shared` request or automatic worktree fallback. **Existing owner:** host agent/user chooses isolation and Canvas applies hardcoded fallback; no separate developer-composed autonomous anti-interference owner. **Proposed owner:** one optional parent-authorized independently composed S2 arbiter scoped to Canvas's local child-launch path and one controlled workspace. **Legitimate choices:** admit if isolated, defer when shared conflict exists, reject a shared launch; not whole-network S3 task assignment or parent S5 policy. **Operational effect:** the existing Canvas createChild call is withheld or run after guarded recheck; no unmanaged shared child on enforce failure. **Feedback:** actual child id, applied isolation, completion/error and release is returned both to the arbiter and parent via the first-party result path. Preserve exact backend/workspace identity and avoid treating browser-local claims as cross-tab atomic authority. Simplest comparator: always use worktree, explicitly serialize in the parent or disallow shared fallback.
